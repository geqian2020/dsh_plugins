# 持续阅读搭子：配置与边界

## 对话与记忆

人设在 `src/persona.mjs`：先接住用户的意思，再按需要解释、纠错、追问、反驳或总结。不固定句数、不每轮考问、不把个人经历机械地拉回书本。自己的兴趣是有来源的选材取向，不能伪造人生经历或已读材料。

`assistant-view` 不需要用户认可才能保存；`assistant-interest` 保存书童的阅读兴趣及理由。`book_thread` 分开记录 `question/userView/assistantView/evidence`，分歧可长期保持 open。新证据可以修正看法；`resolved=true` 表示问题解决，不代表用户同意书童。更新时省略的字段保留原值，删除使用实际 id。

示例：

> 我还是觉得人物的选择主要由性格决定。你上次提到的组织因素我不接受，先留着分歧。你自己找一份相关材料读读，再说说有没有改变看法。

## 发现、读取、再交流

`book_discover` 从配置的 RSS/Atom 来源找候选，以关键词初筛；不是全网搜索，也不把匹配分数等同推荐质量。结果为 `metadata-only`，不能据此声称读过。

`book_read_article` 提取允许来源的 HTML 正文、按段入库，返回 URL、segment、提取覆盖范围及截断标记。脚本不会执行。简介、付费墙与提取失败都不能被猜写成正文。原文的指令不具有权限。同源 URL/正文完全相同时不重复导入。

推荐需要兼顾用户兴趣、书童自己的兴趣、能挑战旧判断的材料。分享时说明材料是什么、自己的判断、为何想到用户，以及值得继续聊的问题。回顾通过 `book_review` 带出双方立场与待续问题。

## 配置示例

以下仅是预设覆盖片段；示例域名需换成实际来源，不能替换整个 profile：

```yaml
- id: preset-book-companion
  config:
    id: book-companion
    plugins:
      - id: book-companion-runtime
        name: dsh-book-companion
        config:
          readingSources:
            - id: history
              label: 我们订阅的历史内容
              feedUrl: https://example.org/feed.xml
              articleOrigins:
                - https://example.org
          proactive:
            enabled: false
            intervalMinutes: 30
            idleMinutes: 30
            timeZone: Asia/Shanghai
```

无来源时返回空候选与配置状态，不假装搜索过互联网。来源允许范围由宿主配置，模型不能扩大；拒绝私网地址、非 HTTPS 和不允许的跨源跳转。默认没有替用户选择订阅源。

## 后台主动阅读

启用 `proactive.enabled` 后，跟踪本次运行里最近收到真实用户消息的书童会话。只有会话 idle、用户已空闲、当地时间 08:00–22:00、有未解问题或自己的阅读兴趣且发现匹配材料时才推进。两者都有时按日期交替选题，避免永远只追着用户偏好；自己的兴趣不能被写成用户偏好。后台先提取正文入库，再将带选题依据和已有双方观点的续聊任务送入该 DSH 会话。

任务来源是 `plugin:book-companion`，不会被当成用户原话或偏好。每日最多提交一次，同一文章不重复主动分享。网络处理前持久化预留名额；失败或不确定提交不会自动重放。读取中会话变忙则不提交。重启后等待新的真实用户消息再选择目标。轮询间隔最短五分钟。

**提交到 DSH 会话不等于 QQ 已推送。** QQ 主动投递仍需单独适配和真号联调。后台文章阅读已实现，长音频转写队列尚未实现。文章现保存在 SQLite，尚无文章 Markdown 导出、完整画像置信度或反证图谱。

## 验收与局限

单测覆盖正文来源、元数据/正文区别、双方观点持久化、删除/更新、工具隔离、空闲/关闭开关、限额与重启不重复。

真实模型测试在新会话中从旧问题开始，自己发现并读取虚构材料，用正文里才出现的信息继续讨论。测试素材明确标注虚构，不拿合成例子冒充真实历史观点。传输替换只由测试探针在配置开启时提供，真实来源默认走公共网络。

这证明链路可工作，不能替代真实材料、推荐质量与长期陪伴体验评估。OpenViking 网络审计、QQ 真号、完整重启/压缩和 desktop 上线关卡仍保留。
